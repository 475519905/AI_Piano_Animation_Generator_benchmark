# 钢琴动画评测协议

## A. 先说明评测问题

区分以下问题，不混报一个“准确率”：

1. MIDI 到左右手/手指：与某份参考指法的标签一致性。
2. 给定参考指法后预测动作：teacher-forced 动作误差。
3. 由模型自己预测指法再生成动作：端到端结果。
4. 最终 DCC 求值结果：经过 IK、手型约束、骨架重定向和曲线插值后的实际动画。
5. 视觉与演奏可信度：独立人工盲评及真实几何审计。

本工具实现部分数值测量，不把第 1–4 项自动等价为第 5 项。

## B. 冻结数据与基线

- 用有权使用的数据。原始录制、模型权重、钢琴/人物资产的许可不能因评测开源而自动公开。
- 按作品组与录制演奏分组。相同演奏的片段、不同摄像机视角、变速/移调，不能分别进入训练和测试。
  同一作品的改编版本原则上也归为同一 `piece_group`；如何识别近重复需记录。
- 若声称对新演奏者/新钢琴泛化，必须分别控制演奏者/乐器划分，不能只留出曲名。
- 分别保留 train、validation、test；在 validation 选参数，在 test 做最后报告。
  看过 test 再修复模型后，该集合成为已使用开发数据，不能继续称“从未见过”。
- 声明检查器无法验证事实上的封存。冻结清单、数据版本/哈希、模型/代码版本、随机种子及查看记录，由实验组织者负责。
- 单独保留合成反例用于测试计分器，不能将其成绩当成真实数据上的泛化成绩。

## C. 固定坐标、时间与取样

- 米、秒、右手键盘坐标系；固定 point/finger/rotation/event ID。
- 真实 MIDI event ID、tempo map、起止时间、参考指法来源与缺失标签策略要可追溯。
- 声明 reference 指法是否进入动作模型输入；不得把参考驱动误差包装成端到端质量。
- 固定 fps 和重采样策略；重采样应在独立适配步骤执行并记录，计分器拒绝错时输入。
- 所有模型使用相同参考、采样时刻、相机和审查片段规则。不对每个预测事后寻找最优延迟/缩放/对齐。
- 若需要对齐作为额外诊断，单列指标及拟合数据，不能替代未对齐结果。

## D. 同时测原始输出与最终动画

原始输出反映模型本身；最终动画反映可交付结果。分别保存 `raw_prediction` 与 `final_evaluated` 报告。
后处理可改善触键也可能增加抖动/僵硬，必须报告同一配置下两阶段的取舍。
固定 IK、骨架映射、平滑和接触投影参数，不针对测试曲逐首调到最好再报统一方法。

导出最终动画时读取实际求值的世界空间骨骼/指尖。控制器目标正好在键上，
并不证明皮肤或指尖实际也在键上。必要时补充真实 mesh 顶点/碰撞审计，v0.1 未实现该审计。

## E. 指标和缺失

逐个报告 [METRICS.md](METRICS.md) 的指标、单位、有效样本量、p95/max 和 missing 状态。
指法可以有多种合法解；姿态也可以有多种风格。对单个参考误差小不等于演奏唯一正确。

接触代理是**参考指定手指→目标键**的条件测量，不是任意手指覆盖全部 MIDI 键事件。
完整皮肤穿模、自碰撞、关节生理安全性、踏板与释键表现需要另外的审查；没测不能写零。
每帧阈值换帧率后不能原样复用，历史内部阈值也不能冒充公开行业标准。

如项目需要验收门槛，先在验证集与人工评审上确定容差、阈值和理由，冻结后再运行测试。
这个仓库不发布一组任意阈值去证明某个私有版本“全部通过”。

## F. 计分器反例

至少检验以下情况会被适当暴露，而不是意外获得好分：
- 全部静止：jerk 很低，但接触/姿态/时序应联合解释。
- 全部同指、全部换成另一只手、弃权：指法/分手准确率与覆盖率应反映问题。
- 悬空 10 mm、目标键 Y 方向偏出、穿入键面：不能只凭 X 对齐判触键成功。
- 高频抖动：jerk 应上升；线性/三次函数在不同 fps 下提供导数单位测试。
- 时间整体偏移、marker ID 顺序颠倒、事件对不上：拒绝静默匹配。
- 缺失接触/碰撞数据、空接触段：必须缺失，不是“零错误”。
- 混合 teacher-forced/端到端或不同后处理报告：拒绝混池。

现有自动测试覆盖相关算术与验证逻辑，但不能取代宿主导出适配器的真实场景测试。

## G. 人工盲评建议（方法规范，不声称已执行）

- 冻结抽样规则，包含快速重复音、和弦、跨距、跨手/换指、长时保持和休止段；保留失败片段。
- 相同视角、分辨率、fps、音频音量、速度和显示时长；随机顺序，隐藏版本/模型标签。
- 评分维度分开：触键/音符关系、手型和换指可信度、运动连贯性、身体动作、整体可用性。
- 对有专业要求的项目请演奏者评审；记录评审者经验与数量、匿名化分数和分歧，不把一人观感当客观认证。
- 评分量表及说明需预先定义。报告原始分布及成对偏好，不仅给最好截图或精选视频。
- 置信区间按独立演奏/作品组进行重采样，不把相邻帧当作大量独立受试样本。
- 取得公开视频/录音/动作与评审数据的必要授权；本仓库只含合成样例。

## H. 可复现发布清单

每次报告附上：协议版本、输入格式/单位、采样/适配器版本、匿名 split 清单与近重复规则、
参考数据版本/哈希、预测代码/权重标识、随机种子、后处理配置、stage/conditioning、
逐演奏报告、micro/macro 规则、缺失项、失败例、人工评审规则和资源开销。

第三方只拿到预测数组和有权取得的参考数据，就应能运行评测器；不应需要登录你的推理服务器。
未分发参考数据时要直说：代码可复现不意味着第三方已能完全重现你的真实成绩。
